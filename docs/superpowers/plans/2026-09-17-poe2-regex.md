# PoE2 Regex Builder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Traditional-Chinese-first Path of Exile 2 web tool that builds short stash/vendor/waystone/tablet search regex from selectable mods.

**Architecture:** Vite + React + TypeScript static SPA. Pure client-side regex package with unit tests. Build-time scripts normalize RePoE-fork PoE2 JSON into `packages/data`. GitHub Actions refresh data; deploy static output to Vercel.

**Tech Stack:** pnpm workspaces, Vite, React 18+, TypeScript, Vitest, Tailwind CSS, GitHub Actions, Vercel.

## Global Constraints

- UI default language: Traditional Chinese (zh-TW); English labels secondary
- Search bar limit display: 250 characters
- Data: public legal sources only (RePoE-fork primary); no login scraping
- Improve on poe2.re: include/exclude, numeric ranges, search, zh-TW first, auto-update pipeline
- Code: clean, maintainable; no secrets required for static site

---

## File map

- `apps/web/` — Vite React UI
- `packages/regex/` — `buildRegex`, shorteners, length helpers + tests
- `packages/data/` — generated `mods.json`, `categories.json`, `presets.json`, `meta.json`
- `scripts/fetch-data.mjs` — download + normalize RePoE-fork
- `scripts/merge-zh.mjs` — merge zh-TW strings when available; fallback EN
- `.github/workflows/update-data.yml` — scheduled/manual data refresh
- `README.md` — zh-TW oriented usage + deploy notes
