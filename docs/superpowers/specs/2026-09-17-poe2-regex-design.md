# PoE2 正則產生器 — 設計規格

日期：2026-09-17  
狀態：已定案（方案 A；使用者略過確認，依自主決策繼續）

## 目標

網頁工具：使用者搜尋／勾選詞條後，產生可貼到遊戲內倉庫、商店、地圖（通靈石）、碑牌搜尋欄的正則。支援包含／排除、數值範圍、繁中優先＋英文。資料隨遊戲版本自動更新。參考 poe2.re 並改進。

成功標準：

- 繁體中文介面為預設；可切換顯示英文詞條名
- 產生字串盡量短，並顯示長度／250 上限；超限明確警告
- 同一次選擇可同時「要」與「不要」詞條，並可設數值下限／上限
- 一鍵複製、分類瀏覽、搜尋、內建預設組合
- 公開合法資料來源；CI 可在新版本資料出現時重建並部署

## 方案選擇

**採用 A：Vite + React + TypeScript 靜態站 + GitHub Actions 資料刷新 + Vercel 部署。**

正則產生純前端；資料為版本化 JSON。不採用 Next.js 全端（B）或 fork poe2.re（C），以降低複雜度並完整擁有繁中與演算法改進。

## 架構

```
apps/web          Vite React UI（繁中預設）
packages/regex    正則縮短與組合（純函式，可單測）
packages/data     建置期產生的 mods / categories / presets JSON
scripts/          從 RePoE-fork（及公開 locale）拉取並正規化
.github/workflows 排程／手動觸發資料更新 → build → deploy
```

資料流：RePoE-fork PoE2 JSON（結構＋英文）→ 建置腳本正規化 → 可選合併繁中 locale／公開解包字串 → `packages/data` → 前端讀取。執行期不爬站。

## 核心模組

### 1. 資料模型

每個可選詞條大致包含：

- `id`、分類（抵抗、生命、速度、地圖詞綴…）
- `labelZh` / `labelEn`
- `match`：用於正則的字面片段（依介面語言選擇繁中或英文匹配字串）
- `kind`：`flag` | `numeric`
- `numeric`（可選）：stat 佔位、預設建議範圍
- `contexts`：`stash` | `vendor` | `waystone` | `tablet`（哪些模式顯示）

### 2. 正則引擎（`packages/regex`）

輸入：已選包含項、排除項、每項數值約束、目前語言。  
輸出：單一正則字串＋長度＋是否超限＋可選診斷。

規則：

- 包含：交替／共同子字串縮短；排除：負向先行（在遊戲搜尋語法允許的前提下）或文件化的替代策略
- 數值：產生能對上遊戲顯示格式的數字模式（含 `%` 等）
- 目標：無已知假陽性的前提下盡量短；無法保證時在 UI 標註
- 硬上限顯示 250（與倉庫搜尋一致）；若某模式實際更短則用該模式上限常數

### 3. 前端

- 頂部：模式切換（倉庫／商店／地圖／碑牌）、語言、長度條、複製／重設
- 左／主區：分類＋搜尋＋勾選；每項可切換包含／排除；數值項可填 min/max
- 預設：一鍵套用常見組合（可本地儲存自訂預設）
- 無障礙：鍵盤可操作；行動裝置可用

### 4. 資料更新

- 主要來源：https://repoe-fork.github.io/poe2/（`mods`、`stat_translations`、`item_classes` 等）
- 繁中字串：僅使用公開合法的 client locale／社群解包匯出；禁止需登入或 ToS 禁止的抓取
- Actions：每日或手動；偵測上游版本號變化才 commit 新 data 並觸發部署
- UI 顯示目前資料對應的遊戲／資料版本

### 5. 部署

- Vercel 連到 Origin／Git 倉庫靜態輸出
- 環境無祕密亦可運作（純靜態）

## 非目標（v1 不做）

- 帳號／雲端同步預設
- 完整交易網站 API 整合
- 遊戲內 overlay
- PoE1

## 測試

- `packages/regex`：縮短、包含／排除、數值、長度邊界的單元測試
- 前端：關鍵互動的基本測試即可
- 建置腳本：對固定 fixture 做 snapshot

## 實作順序

1. Scaffold monorepo（Vite app + regex package + data fixtures）
2. 正則引擎＋測試
3. 最小 UI（搜尋、勾選、複製、長度）
4. 接上 RePoE 建置腳本與真實資料
5. 繁中標籤／匹配字串合併
6. 預設、排除、數值範圍打磨
7. Actions + Vercel 部署說明

## 風險

- 遊戲搜尋正則語法與一般 JS 正則不完全相同 → 以實測與社群已知行為為準，引擎內集中適配
- 繁中匹配字串來源若落後英文 → UI 標示缺字串的詞條，並允許僅英文匹配後備
- 250 字元下選擇過多 → 即時長度警告並建議取消低優先項
